# KAPy bias adjustment configuration

*Bias adjustment is the process by which the outputs of a climate model are post-processed so that they match specific characteristics of the observed climate during a common period of time. In KAPy we wrap methods in the `xsdba` package, previously part of `xclim. The method employed is chosen via the `method` field, with the following valid options: 
 * `xsdba-scaling` - [Scaling bias-adjustment](https://xsdba.readthedocs.io/en/stable/apidoc/xsdba.html#xsdba.adjustment.Scaling).
 * `xsdba-eqm` - [Empirical Quantile Mapping](https://xsdba.readthedocs.io/en/stable/apidoc/xsdba.html#xsdba.adjustment.EmpiricalQuantileMapping). 
 * `xsdba-dqm` - [Detrended Quantile Mapping](https://xsdba.readthedocs.io/en/stable/apidoc/xsdba.html#xsdba.adjustment.DetrendedQuantileMapping). 
  
 In addition, the ability to add custom indicator functions may be added in a future verison. 
   For more information, see the documentation in the `xsdba` package: https://xsdba.readthedocs.io/en/stable/index.html*

## Properties

- <a id="properties/id"></a>**`id`** *(string, required)*: Unique identifier for the bias adjustment task. Cannot contain a space or comma. Must match pattern: `^[^ ,]+$` ([Test](https://regexr.com/?expression=%5E%5B%5E%20%2C%5D%2B%24)). Items must be unique.
- <a id="properties/enabled"></a>**`enabled`** *(string or null, required)*: Determines whether the row be used in the workflow. A non-empty value indicates not to use that row.
- <a id="properties/output_dataset_code"></a>**`output_dataset_code`** *(string, required)*: DatasetCode that will be associated with bias-adjusted output. Note that the cominbation of variable name and DatasetCode must not be a duplicate of other combinations names found in the configuration of KAPy. This variable primarily serves to distinguish between raw and bias-adjusted variables e.g. `CORDEX` and `CORDEX-cal` The exact choice is not important, but it is recommended to adopt a consistent approach throughout the project.
- <a id="properties/variable_to_adjust"></a>**`variable_to_adjust`** *(string, required)*: The name of the variable to bias adjust, drawn from the list of primary and secondary variables. If the variable cannot be found, an error will be raised. KAPy assumes that the same variable name is used for both the model and observational data sources.
- <a id="properties/dataset_to_adjust"></a>**`dataset_to_adjust`** *(string, required)*: The dataset that will be bias adjusted e.g.  'CORDEX'. This is most commonly the output of a climate model, but need not be.
- <a id="properties/reference_dataset"></a>**`reference_dataset`** *(string, required)*: The dataset that will be used as the reference  data source to bias-adjust against, such as `ERA5`. Most commonly this will be an observational data set, a reanalysis or similar but it need not be. However, the combination of climate variable and dataset code should uniquely identify a single file within the variable palette of KAPy - if not, an error will be raised.
- <a id="properties/output_grid"></a>**`output_grid`** *(string, required)*: Chooses the grid that the output of bias adjustment procedure ends on. Arguments can be made that the target dataset should be adjusted to the grid of the reference data (`reference`), or conversely, that the reference dataset should be adjusted onto the grid of the target dataset (`target`). In cases where there is a substantial difference in resolutions between the grids, this decision can potentially lead to the loss by omitting points from the higher resolution grid: however, this may also be desirable in some cases. Given that the appropriate choice will depend on the specifics of the system, this choice is therefore left to the user, as configured by this option. . Must be one of: "reference" or "target".
- <a id="properties/training_period_start"></a>**`training_period_start`** *(string, required)*: Start year of the training period. Data after and including 1 Jan of this year will be used for training the bias adjustment procedure. Must match pattern: `^\d{4}$` ([Test](https://regexr.com/?expression=%5E%5Cd%7B4%7D%24)).
- <a id="properties/training_period_end"></a>**`training_period_end`** *(string, required)*: End year of the training period. Data before and including 31 Dec of this year will be used for training the bias adjustment procedure. Must match pattern: `^\d{4}$` ([Test](https://regexr.com/?expression=%5E%5Cd%7B4%7D%24)).
- <a id="properties/method"></a>**`method`** *(string, required)*: Bias adjustment method to be used. See above for a clarification of options. Must be one of: "xsdba-scaling", "xsdba-eqm", or "xsdba-dqm".
- <a id="properties/grouping"></a>**`grouping`** *(string)*: Apply bias-adjustment independently of each time grouping selected here. Must be one of: "none", "dayofyear", "month", or "season".
- <a id="properties/kind"></a>**`kind`** *(string, required)*: The adjustment kind, either additive ('+') or multiplicative ('*'). Must be one of: "+" or "*".
- <a id="properties/additional_arguments"></a>**`additional_arguments`** *(string, required)*: Additional arbitrary arguments specified as a dict to be passed to the function via keyword arguments. e.g. `{'kind'='+', group='time.month'}`. Can be an empty dict or empty string if no there are no additional parameters. e.g. `{}` .
