# KAPy indicator configuration

*Configuration of indicators is set through a tab-separated table, with one row per indicator. The available configuration options are described here. All options are required*

## Properties

- <a id="properties/id"></a>**`id`** *(string)*: A unique id for this processing group. Cannot contain a space or comma. Must match pattern: `^[^ ,]+$` ([Test](https://regexr.com/?expression=%5E%5B%5E%20%2C%5D%2B%24)). Items must be unique.
- <a id="properties/indicator_codes"></a>**`indicator_codes`** *(string, required)*: Codes of the set of indicators to be generated, as a comma-separated list. Each code must be unique. Items must be unique.
- <a id="properties/enabled"></a>**`enabled`** *(string or null, required)*: Determines whether the row be used in the workflow. A non-empty value indicates not to use that row.
- <a id="properties/description"></a>**`description`** *(string, required)*: Description of the indicator(s) defined here. Stored in the output database.
- <a id="properties/variables"></a>**`variables`** *(string, required)*: Comma-separater list of input variables required to calculate the indicator. Must be at least one specified.
- <a id="properties/datasets"></a>**`datasets`** *(string, required)*: Comma-separated list of dataset IDs for which the indicator is to be calculated. IDs should match those defined as primary (input), secondary, bias-adjusted or tertiary variables. In addition, `all` selects all datasets.
- <a id="properties/seasons"></a>**`seasons`** *(string, required)*: Comma-separated lists of season IDs over which the indicator is to be calculated. IDs should match those in the [seasons configuration](seasons.md) table. In addition, `all` selects all seasons.
- <a id="properties/timeBinning"></a>**`timeBinning`** *(string, required)*: Time bins over which indicators are calculated. In the case of choosing `periods`, the indicator will be calculated for all periods defined in the [periods configuration](periods.md) table. Indicators can also be calculated across a whole year, using the `years`options. Months were previously available, but have been removed. Must be one of: "periods" or "years".
- <a id="properties/deltaType"></a>**`deltaType`** *(string, required)*: How to calculate the change in variables (the *delta*) relative to the reference period. Two options are permitted: `subtract`, where changes in the indicator relative to the mean over the reference period are calculated by subtraction, and `divide` where the change is expressed as the ratio of the indicator to the mean over the reference period. In both cases, the first period defined in the periods table is used as the reference period. Must be one of: "subtract" or "divide".
- <a id="properties/statistic"></a>**`statistic`** *(string, required)*: Statistic to be used to calculate the indicator. KAPy has eight basic types of indicators built in. 1) `mean` calculates an average across the period. 2)`count` calculates the average number of days per year in the period above or below a threshold. Additional parameters must be supplied via the `additional_arguments` field: `threshold` is the threshold value, and `op` is the comparison operator - one of `>`,`gt`,`<`,`lt`,  `>=`, `ge`, `<=` or `le`.  3) `meanmax` calculates the maximum value of the variable over the season or year - in cases where there is period binning enabled, the average annual maximum is calculated. 4) `meanmin` calculates the average minimum in the same manner as `meanmax` 5) ´max' calculates the maximum value of the indicator across the entire binning period 6) `min` calculates the minimum value across the binning period 7) `quantile` calculates the value of a given quantile. An additional parameter `q` must be suppliedin the `additional_arguments` field. 8) `custom` calls the function defined in `customScriptPath` and `customScriptFunction` and utilised arguments supplied as a dictionary in `additional_arguments`. Must be one of: "custom", "mean", "count", "max", "min", "meanmax", "meanmin", or "quantile".
- <a id="properties/skipna"></a>**`skipna`** *(string, required)*: If True, NaN values in the climate variables are ignored and statistics e.g. means are calculated around them. If False, NaNs propigate, and the presence of a single NaN in a time series will cause all subsequent values to be NaN. It is generally recommended to set this parameter to False, unless there is a specific use-case where missing values need to be handled. Note that if all values in a timeseries are NaN, the resulting indicator will also be NaN. Must be one of: "true" or "false".
- <a id="properties/additional_arguments"></a>**`additional_arguments`** *(string, required)*: Additional arbitrary arguments specified as a dict to be passed to the function via keyword arguments. e.g. `{'threshold':'25','op':'gt'}`. If no there are no additional parameters. an empty dict should be supplied i.e. `{}`.
- <a id="properties/customScriptPath"></a>**`customScriptPath`** *(string, required)*: If `statistic` is set to `custom`, this field is used to identify the path to a custom script, if applicable.
- <a id="properties/customScriptFunction"></a>**`customScriptFunction`** *(string, required)*: Name of the function in `customScriptPath` to be used for calculating the indicator,  if applicable.
